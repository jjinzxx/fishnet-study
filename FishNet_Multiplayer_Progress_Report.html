01

요약

현재는 Steam Lobby 참가자가 FishySteamworks를 통해 FishNet에 연결되고, Host가 FishNet Client ID와 Steam ID64의 대응 관계를 확인하는 단계까지 구현했습니다.

현재 체크포인트 [Unity] 멀티플레이 (21)까지 구현하고 Host 단독 실행으로 확인했습니다.
다음 작업 매핑된 Steam ID64가 현재 Steam Lobby 멤버인지 서버에서 검사합니다.
현재 가능한 검증 Steam 초기화, Host Lobby 생성, FishNet 인증 1 / 1, Host ID 매핑과 정상 종료입니다.
외부 실행 환경 필요 서로 다른 Steam 계정으로 Guest 참가, 인증, 퇴장, 씬 이동을 다시 검증해야 합니다.
진행률과 검증률은 구분합니다. 코드와 Inspector 구성이 완료된 기능이라도 두 계정에서 재현하지 못한 항목은 구현 완료·검증 보류로 표시합니다. 따라서 단순한 백분율로 전체 완성도를 표현하지 않습니다.
02

현재 스터디 목표

캐릭터나 전투를 만드는 것이 아니라 세 네트워크 계층이 올바르게 연결되는지 검증하는 것이 목표입니다.

Heathen Steamworks

Steam 플랫폼과 Lobby 계층입니다.

  • Steam API 초기화
  • Lobby 생성·검색·참가·퇴장
  • Lobby 멤버와 방장 정보
  • Steam ID64와 친구 초대
→

FishySteamworks

FishNet의 Steam Transport 계층입니다.

  • 방장 Steam ID를 접속 주소로 사용
  • Steam P2P 또는 Relay 연결
  • FishNet 패킷 운송
→

FishNet

세션과 서버 권한 계층입니다.

  • 접속자와 인증 상태 관리
  • 준비·세션 상태 동기화
  • 서버 요청 검증
  • 네트워크 씬 이동
현재 완료 조건 Steam Lobby의 Guest가 방장 Steam ID64로 FishNet에 연결되고, 서버가 해당 연결자의 신원과 Lobby 소속을 확인하며, 간단한 준비 상태와 Title → Main 네트워크 전환을 동기화하면 현재 스터디 목표를 달성합니다.

05

지금까지 완료한 작업

초기 Mock UI부터 실제 Steam Lobby와 FishNet 연결 상태 표시까지 단계적으로 진행했습니다.

  1. 프로젝트와 UI 실습 환경 구성

    메인 메뉴, 모드 선택, 협동전, 방 목록, 방 생성, 대기실 UI를 Title 씬에 구성하고 2명/4명 방 설정을 적용했습니다.

  2. Steamworks 개발 환경 구성

    Heathen Toolkit 3.6.0, Steamworks.NET, App ID 480 초기화와 로컬 사용자 정보를 확인했습니다.

  3. 실제 Steam Lobby 흐름 구현

    Lobby 생성·검색·참가·퇴장, 방 이름·최대 인원·멤버·방장 정보를 UI에 표시하도록 구성했습니다.

  4. FishySteamworks Transport 구성

    FishNet NetworkManager의 Transport를 FishySteamworks로 연결하고 종료 순서 충돌을 방지했습니다.

  5. Guest의 FishNet 연결 절차 구현 · (19)

    Guest가 Steam Lobby Owner의 Steam ID64를 접속 주소로 사용하며, FishNet OnAuthenticated 이후에만 대기실로 진입합니다.

  6. Host의 인증 인원 표시 구현 · (20)

    Host가 활성화되고 인증된 FishNet 연결만 집계하여 Steam Lobby 인원과 비교하고 대기실 상태 문구를 갱신합니다.

  7. FishNet Client ID와 Steam ID64 매핑 · (21)

    FishNet 인증 성공 시 Transport 주소에서 Steam ID64를 얻고, Host 로컬 Client ID 32767이 Lobby Owner Steam ID64와 일치하는 것을 확인했습니다.

  8. 독립된 두 Steam 계정 통합 재검증

    현재 한 대의 PC만 사용할 수 있어 Guest 참가 후 1 / 2 → 2 / 2 변화와 퇴장 복귀 검증을 보류했습니다.

현재 구현 및 검증 상태

코드 존재 여부, Host 단독 확인 가능 여부, 독립된 두 계정 확인 여부를 분리했습니다.

검증 항목 구현 한 PC 두 계정 재검증
App ID 480 Steam 초기화 완료 확인 가능 불필요
Host Lobby 생성과 FishNet Host 시작 완료 확인 가능 불필요
Host FishNet 인증 인원 1 / 1 완료 확인 가능 불필요
Host Client ID 32767과 Steam ID64 매핑 완료 실행 확인 Guest 매핑만 보류
Guest Lobby 검색·참가 완료 독립 Guest 불가 재검증 보류
Guest FishNet 연결과 인증 완료 대기 완료 독립 Guest 불가 재검증 보류
Host의 1 / 2 → 2 / 2 표시 구현 완료 확인 불가 검증 보류
Guest 퇴장 후 Host 1 / 1 복귀 구현 완료 확인 불가 검증 보류
한 PC에서 Editor와 Build를 동시에 실행해도 독립 Guest가 되지 않습니다. 두 프로세스가 같은 Steam 클라이언트와 같은 Steam ID를 사용하기 때문입니다. 따라서 같은 계정의 중복 실행 결과를 2인 멀티플레이 성공으로 기록하지 않습니다.

한 PC에서 지금 확인할 수 있는 회귀 검사

  • Steam API가 App ID 480으로 초기화됩니다.
  • Host가 2인 또는 4인 Lobby를 생성합니다.
  • 대기실에 Host 한 명과 방장 표시가 나타납니다.
  • FishNet 인증 인원이 1 / 1로 표시됩니다.
  • Host Client ID와 Lobby Owner Steam ID64가 정확히 대응됩니다.
  • 나가기 후 다시 방을 생성할 수 있습니다.
  • Play Mode 종료 시 Steamworks 초기화 오류가 발생하지 않습니다.

현재 포함

이번 스터디에서 완료할 항목

  • Steam Lobby 생성·검색·참가·퇴장

현재 제외

실제 게임 연동 단계로 미룰 항목

  • 캐릭터 선택과 중복 방지
  • 미선택 캐릭터 랜덤 배정
  • 카드·전투·경로·보상·상점·캠프

  • 호스트 마이그레이션

현재 확인된 기술 부채와 주의점

  • Main.unity가 아직 없고 Editor Build Settings에는 Title.unity만 등록되어 있습니다.
  • StartGameButton은 아직 동작이 연결되지 않았으며 현재 코드가 항상 비활성화합니다.
  • 기존 ReadyRequestSender.cs는 과거 FishNet Test 씬용 학습 코드이며 현재 Title Steam 흐름에 통합되지 않았습니다.
  • Guest가 인증된 뒤 Host 연결이 끊겼을 때 방 목록 UI로 자동 복귀시키는 지속적인 연결 종료 처리가 아직 없습니다.
  • FishNet Client ID를 Steam ID나 영구 사용자 ID로 사용하면 안 됩니다.
  • 현재 Windows 빌드 산출물은 (19)~(21) 반영 전 생성본이므로 최종 2인 검증 전에 최신 코드로 다시 빌드해야 합니다.
09

최종 완료 체크리스트

아래 항목이 모두 충족되면 현재 멀티플레이 접속 검증 스터디를 마무리할 수 있습니다.

Steam 및 Transport

  • Steam Lobby 생성·검색·참가·퇴장이 동작합니다.
  • Guest가 Lobby Owner Steam ID64로 연결합니다.
  • Steam P2P/Relay를 통해 FishNet 연결이 성립합니다.
  • 친구 초대 수락으로 같은 Lobby에 참가합니다.

FishNet 및 서버 검증

  • FishNet Client ID와 Steam ID64가 대응됩니다.
  • 서버가 Lobby 멤버가 아닌 접속을 거부합니다.
  • 준비 상태가 서버 기준으로 동기화됩니다.
  • Host 시작 권한을 서버가 최종 검사합니다.

씬과 수명주기

  • 모든 참가자가 Title → Main으로 이동합니다.
  • Main에서 동일한 세션 상태를 확인합니다.
  • Guest 퇴장과 Host 종료가 안전하게 처리됩니다.
  • 종료 시 Steamworks 초기화 오류가 발생하지 않습니다.

실행 환경

  • 서로 다른 두 Steam 계정에서 전체 흐름을 검증합니다.
  • 2인 방의 실제 정원을 확인합니다.
